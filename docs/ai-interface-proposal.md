# AI lane interface proposal for lead review

The frozen `NluFrame` exposes only `language`, `intent`, and `confidence`; its language enum is limited to `es`/`pt`. The AI lane keeps richer extraction in `NluResult` without changing that shared class. The lead can call `understand(message, country=..., bank_clock=..., client=...)` and use `result.frame` wherever the existing contract is required. It must consult `result.extracted.language` and `result.clarification` before using the two-value `frame.language`: mixed/other currently maps to `es` solely to satisfy the frozen type. `result.slots` carries normalized amount, currency, and date range; `result.degraded` indicates deterministic fallback. The lead should continue to obtain identity, transactions, policy decisions, and action authority from its own trusted services.

For the next interface version, propose optional `slots`, `risk_cues`, `customer_confirms`, and `human_requested` fields on `NluFrame`, plus explicit `mixed` and `other` language values, or a separately versioned internal NLU result contract. Expanding the language enum needs consumer review. The `ResponsePlan` interface already works as the input and output of `build_reply`; the builder returns a validated copy with a grounded or template reply.

Integration checks needed in the lead lane: pass only contract-allowed masked facts and opaque handles to `build_reply`; send every API reply through its DLP check; record `StructuredClient.records` metadata with the execution record; choose deterministic mode when `degraded` is true; never interpret extracted risk cues or model text as a policy decision or action confirmation.
