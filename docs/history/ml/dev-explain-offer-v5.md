[NLU prompt v5.1](../../../prompts/nlu/v5.md) has SHA-256 `e40182de2f232932a12d61d722be5e6356d787217048378fbc2a84f330d241cc`. `ExtractedNlu.unfamiliar_charge` is true only for bare unfamiliarity inside a `charge_inquiry`; explicit denials remain `dispute_charge` with the flag false. Neutral what/why and pending-status questions are forced false. For other inquiries, postprocessing preserves the model's semantic judgment instead of limiting it to a keyword list. The deterministic fallback recognizes common ES/pt-BR cues, and filing requests alone do not set the flag. The AI boundary supplies only an explicit `awaiting_recognition` flag and allowlisted, redacted charge display facts. Without the flag, any model recognition field is cleared. In the waiting state, a clear denial or filing request is `denied`, explicit ownership is `recognized`, and uncertainty or isolated yes/no is `unsure`; a new unrelated request leaves the signal absent. `unfamiliar_charge` is false in this waiting state. Both fields remain inside `ExtractedNlu`; `NluFrame` and action authorization are unchanged. `customer_confirms` never confirms a write. The signals are recorded as decision metadata, without persisting model reasoning.

The ES and pt-BR offer templates display the selected charge's merchant, amount/currency, date and recorded status, then ask whether it remains unfamiliar and offer a dispute proposal. They claim no filing, refund or completed action. The renderer cites trusted transaction fields to the [grounding verifier](../../../src/aclara/agent/nlg/grounding.py), which rejects uncited numbers, statuses, merchants and sensitive/instruction text. The verifier now recognizes day numbers from ISO timestamps and normalized grouped amounts, so legitimate localized dates and currency values pass without admitting a different value.

It does not modify the frozen cases or derive gold from model behavior. It requires the lead's Step 3 additions before end-to-end execution: the response literal and outcome in `ResponsePlan`, `offer_dispute` in the scenario schema/observed actions, a nonterminal simulator transition, and scorer handling for a valid `explain_status` event followed by `dispute_filed`. The current scorer otherwise marks that legitimate sequence as `materially_incorrect_outcome`. These are lead-owned changes; this PR does not edit them.
