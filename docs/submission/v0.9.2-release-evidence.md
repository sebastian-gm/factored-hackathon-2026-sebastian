## Judge path and authority

One judge password/OTP login → select profile → request a human in Customer
Chat → **Agent Desk** → **Abrir la cola de esta visita / Abrir a fila desta
visita** → inspect the masked packet → **Tomar solicitud / Assumir solicitação**
→ independently verified assignment. No second staff credential is needed.
The button creates and redeems a five-minute invitation with the same visit's
existing cookie, then independently reads membership back.

The grant adds masked queue list/detail and claim only. It neither changes the
profile's existing trusted role or customer scope nor grants new banking, Ops,
transcript, trace or reset authority. Resolution is unavailable in this realm.
Valid profile switching/restart preserves the visit's membership; other visits
and owner-demo invitations are denied. Logout, expiry, judge OFF and
password/configuration/binding rotation revoke membership and cached claims.
The actual selected capability is revalidated inside the controller transaction
before invitation consumption, including concurrent profile switching.

See the [API/session and threat contract](judge-staff-access.md),
[README judge guide](../../README.md#judge-quickstart--submission-draft) and
[browser quick-start](../../apps/web/JUDGE-TOUR.md).
Separately authenticated staff still uses its existing invitation workflow.
