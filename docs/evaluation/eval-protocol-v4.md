# Independent v4 held-out protocol

V4 is a new blind confirmation suite. V3 was opened for development and is no
longer held out. Gold for v4 comes only from
[ADR-0015](../adr/0015-post-v2-conversation-and-policy-contract.md) and the
[written conversation contract](../../contracts/interfaces/conversation-policy-v3.md).
No system output, post-v3 failure analysis, policy implementation, or old
template list was used to write it. The author created new interaction families
and wording before any execution.

## Gold, conversation and structural freeze

Each authored template explicitly declares its expected terminal path and
minimum reason set from the written contract. The tool renders references and
action/readback requirements; it does not call `aclara.policy`, instantiate a
system, or infer labels by observing behavior. Gold preserves all applicable
evidenced reasons as minimum sets, with contract routing and priority. A
handoff readback never substitutes for a committed-case readback.

The reactive tables contain explicit candidate choices and contextual replies
to dispute offers. Uncertainty has explicit clarification replies; offer
messages cannot confirm a write. Action confirmation is separate. The generic
fallback asks for clarification and never authorizes a write. Multiple initial
messages remain in the same authenticated session where required by the
contract.

`BANK_CLOCK=2026-06-18T06:00:00Z` has business-date anchor **2026-06-17**. Date
arithmetic uses that anchor, as required by [contract §5](../../contracts/interfaces/conversation-policy-v3.md#5-age-convention-and-worked-boundary),
rather than the UTC calendar date. Relative-date wording uses the same anchor.

The authoring preflight checks schema, action/predicate/reason vocabulary,
references, protected-field names, explicit reply tables, known fault hooks,
case/category/language counts, test partition, unique owned products and all
customer exclusions. A mechanical comparison hashes prior message/template
fields without exposing their wording or using their gold. The zero exact
overlap finding does not prove semantic independence. Native organizer IDs are
also checked for absence from the release.

`MANIFEST.sha256` hashes every release file except itself. Its file SHA-256 is
reported to Sebastian at freeze. Private bindings and frozen release files
cannot be overwritten by the authoring tool. Verification reads them back and
checks their hashes and the binding mode. Any later defect is documented; do
not edit gold to fit execution or silently replace the manifest.

**Only structural verification has run. No B1/P execution, API conversation,
model call, fault activation, serving validation or behavioral correctness
measurement was performed on v4.** The post-v3 stale-OTP simulator renewal is
a release dependency. The execution owner must verify it, serving ownership,
fault activation and durable readbacks at the authorized release gate.
