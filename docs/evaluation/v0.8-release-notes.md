## Concurrency and attribution

Runtime events, the AI call cursor and provider records/deadlines use request
contexts. Provider network calls no longer hold a process-wide chat lock. A
full-turn Postgres session advisory lock still serializes the same authenticated
session across workers; transactional/customer locks, RLS and confirmation
version checks remain. Per-worker admission is five active turns and 64 total
active/waiting turns. Database connections and cancellation release are bounded.
Authored tests exercise concurrent provider attribution, two-worker same-session
ordering, queued/held-lock cancellation and atomic reserve-before-call budgets.
